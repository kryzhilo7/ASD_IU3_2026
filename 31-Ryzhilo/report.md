## Задача 1. Максимум и минимум

**Идея.** За один проход по массиву поддерживаем текущие минимум и максимум. Начальные значения берём из
первого элемента. Все последующие числа сравниваются с текущими границами.

**Асимптотика.** Один проход, на каждом элементе не более двух сравнений: не больше `2(n − 1)` сравнений,
итого `Θ(n)`. Меньше `n` элементов просмотреть нельзя: любой пропущенный может оказаться экстремумом.
Память — `O(1)`: массив не сохраняется, используются только текущий элемент, минимум, максимум и счётчики.

| Вход                      | Ответ                        | Почему важен                                            |
|---------------------------|------------------------------|---------------------------------------------------------|
| `[3, 1, 2]`               | min 1, max 3                 | базовый случай                                          |
| `[5, 5, 5]`               | min 5, max 5                 | все элементы равны: min и max совпадают                 |
| `[2, 1]` и `[1, 2]`       | min 1, max 2                 | минимальный размер, не зависит от порядка               |
| `[-7, -3, -9]`            | min -9, max -3               | все числа отрицательные: нельзя начинать с нуля         |
| `[MAX_VALUE, MIN_VALUE]`  | оба крайних значения `int`   | проверка начальных значений и отсутствия переполнения   |
| 99 999 элементов          | верный ответ                 | верхняя граница `n < 10^5`                              |

## Задача 2. Индекс первого вхождения

**Идея.** Идём по массиву слева направо и останавливаемся на первом элементе, равном `x`: он и есть первое
вхождение. Если цикл дошёл до конца, выводим `-1`.

**Асимптотика.** Худший случай (элемента нет или он последний): `n` сравнений, `O(n)`. Лучший случай поиска:
элемент стоит первым, `O(1)`, но чтение всего ввода всё равно линейно. Память: `O(n)` массив, `O(1)` дополнительно.

| Вход                      | Ответ | Почему важен                                                     |
|---------------------------|-------|------------------------------------------------------------------|
| `[4, 8, 15, 16, 23, 42]`, `x = 15` | `2`   | базовый случай                                         |
| `[7, 1, 7]`, `x = 7`      | `0`   | дубликаты: возвращается именно первое вхождение                  |
| `[1, 2, 3, 4]`, `x = 4`   | `3`   | элемент на последней позиции: проверка границы цикла             |
| `[1, 2, 3]`, `x = 7`      | `-1`  | элемента нет                                                     |
| `[-1, 0, -1]`, `x = -1`   | `0`   | отрицательные числа                                              |

## Задача 3. Подсчёт вхождений

**Идея.** Один проход со счётчиком: для каждого элемента, равного `x`, увеличиваем `count`. Счётчик типа `int`
достаточен, так как количество вхождений не превышает `n`.

**Асимптотика.** Один проход по `n` элементам: `Θ(n)`. Досрочно выйти нельзя: нужны все вхождения.
Память: `O(n)` массив, `O(1)` дополнительно.

| Вход                      | Ответ | Почему важен                                         |
|---------------------------|-------|------------------------------------------------------|
| `[1, 2, 1, 3, 1]`, `x = 1`| `3`   | базовый случай                                       |
| `[1, 2, 3]`, `x = 7`      | `0`   | элемента нет: ответ 0, а не ошибка                   |
| `[4, 4, 4]`, `x = 4`      | `3`   | все элементы равны `x`: максимальное значение счётчика |
| `[-1, 0, -1]`, `x = -1`   | `2`   | отрицательные числа                                  |
| `[0, 0, 5]`, `x = 0`      | `2`   | ноль как искомое значение                            |

## Задача 4. Все индексы элемента

**Идея.** Один проход слева направо: индекс каждого элемента, равного `x`, дописываем в `StringBuilder`
через пробел. Так как обход идёт по возрастанию индексов, сортировка результата не нужна.
Результат — последовательность неизвестной заранее длины, поэтому её накапливаем в `StringBuilder`, а не
в массиве с догоном размера и не в `ArrayList<Integer>` (лишняя упаковка `int` в `Integer`).

**Асимптотика.** Один проход, `n` сравнений и не более `k` дописываний (`k` — число вхождений, `k ≤ n`):
`Θ(n)`. Память: массив `O(n)`, строка ответа `O(k)`. Если вхождений нет, выводится пустая строка.

| Вход                        | Ответ        | Почему важен                                                    |
|-----------------------------|--------------|-----------------------------------------------------------------|
| `[5, 1, 5, 2, 5]`, `x = 5`  | `0 2 4`      | базовый случай, порядок возрастания                             |
| `[1, 2, 3]`, `x = 7`        | пустая строка| элемента нет: не должно быть ошибки                             |
| `[9, 9, 9, 9]`, `x = 9`     | `0 1 2 3`    | все элементы совпадают, `k = n`: максимальный размер ответа     |
| `[3, 1, 2, 3]`, `x = 3`     | `0 3`        | совпадения на обеих границах массива: типичная ошибка off-by-one|
| 99 999 элементов `x`        | все индексы  | верхняя граница `n`; сборка вывода не должна быть `O(n²)`       |

## Задача 5. Сумма элементов на чётных позициях

### Условие

Дан массив из n целых чисел. Требуется найти сумму элементов
с чётными индексами: 0, 2, 4 и так далее.

Индексация начинается с нуля. Учитывается чётность индекса,
а не самого значения элемента.

### Идея решения

Сначала считывается размер n, затем элементы сохраняются
в массив numbers.

Суммируются элементы на индексах 0, 2, 4 и далее. Чётность самих значений не учитывается.
Для суммы используется long, чтобы избежать переполнения int.

### Асимптотика

**Время — O(n).**

Чтение требует O(n), суммирование ceil(n/2) элементов — O(n). Итоговая сложность O(n).

**Память — O(n).**

Для хранения входных данных создаётся массив из n элементов.
Остальные переменные занимают O(1) памяти.

### Примеры ручной проверки

**1. Массив нечётной длины**

Ввод:

```text
5
1 2 3 4 5
```

Ожидаемый вывод:

```text
9
```

Складываются элементы с индексами 0, 2 и 4: 1 + 3 + 5 = 9.

**2. Проверка выбора по индексу**

Ввод:

```text
4
1 100 3 200
```

Ожидаемый вывод:

```text
4
```

В сумму входят значения 1 и 3, поскольку их индексы чётные.
Значения 100 и 200 не учитываются.

**3. Отрицательные значения**

Ввод:

```text
5
-1 8 -2 8 -3
```

Ожидаемый вывод:

```text
-6
```

Отрицательные элементы на чётных индексах также включаются в сумму:
−1 + (−2) + (−3) = −6.

**4. Сумма, превышающая диапазон int**

Ввод:

```text
3
2147483647 0 2147483647
```

Ожидаемый вывод:

```text
4294967294
```

Результат превышает максимальное значение int,
но помещается в long.

**5. Минимальный допустимый размер**

Ввод:

```text
2
7 100
```

Ожидаемый вывод:

```text
7
```

При n = 2 единственный чётный индекс — 0.

## Задача 6. Элементы больше среднего

### Условие

Дан массив из n целых чисел. Требуется найти количество элементов,
строго больших среднего арифметического массива.

По условию сумма элементов делится на n, поэтому среднее является целым.

### Идея решения

При чтении элементы сохраняются в массив, одновременно вычисляется
их сумма. Для суммы используется long, поскольку результат сложения
нескольких int может превысить диапазон int.

После чтения вычисляется среднее: average = sum / n.
Затем выполняется второй проход по массиву. Если элемент строго
больше average, счётчик увеличивается.

Элементы, равные среднему, не учитываются.

### Асимптотика

**Время — O(n).**

Чтение и вычисление суммы требуют одного прохода.
Для подсчёта элементов выше среднего выполняется ещё один проход.

**Память — O(n).**

Хранится массив из n элементов. Сумма, среднее и счётчик
занимают O(1) дополнительной памяти.

### Примеры ручной проверки

**1. Разные значения**

Ввод:

```text
5
1 2 3 4 5
```

Ожидаемый вывод:

```text
2
```

Среднее равно 3. Строго больше него два элемента: 4 и 5.

**2. Все элементы равны среднему**

Ввод:

```text
4
7 7 7 7
```

Ожидаемый вывод:

```text
0
```

Проверяется строгость сравнения.

**3. Отрицательное среднее**

Ввод:

```text
3
-3 -1 -2
```

Ожидаемый вывод:

```text
1
```

Среднее равно −2. Только −1 больше среднего.

## Задача 7. Второй максимум

### Условие

Дан массив из n различных целых чисел.
Требуется найти второй по величине элемент.

### Идея решения

После чтения массива первые два элемента используются
для начального определения максимума и второго максимума.

Далее рассматриваются остальные элементы.

Если очередное число больше максимума, прежний максимум
становится вторым, а новое число — первым.

Если число не больше максимума, но больше второго максимума,
обновляется только второй максимум.

После каждого шага переменные содержат два наибольших значения
среди уже рассмотренных элементов.

### Асимптотика

**Время — O(n).**

Чтение массива и поиск двух наибольших значений требуют
линейного числа операций.

**Память — O(n).**

В данной реализации хранится весь массив.
Для самого поиска достаточно O(1) дополнительных переменных.

### Примеры ручной проверки

**1. Неупорядоченный массив**

Ввод:

```text
5
3 9 1 7 2
```

Ожидаемый вывод:

```text
7
```

Максимум равен 9, второй максимум — 7.

**2. Отрицательные числа**

Ввод:

```text
4
-5 -2 -9 -1
```

Ожидаемый вывод:

```text
-2
```

Проверяется правильная инициализация без использования нуля.

**3. Два элемента**

Ввод:

```text
2
2147483647 -2147483648
```

Ожидаемый вывод:

```text
-2147483648
```

При двух различных элементах второй максимум — меньший из них.

## Задача 8. Фильтрация по знаку

### Условие

Дан массив целых чисел. Требуется сформировать два массива:
из положительных и из отрицательных элементов.

Порядок внутри каждой группы должен совпадать с исходным.
Нули не включаются ни в одну группу.

### Идея решения

При чтении исходного массива подсчитываются количества
положительных и отрицательных элементов.

Затем создаются два массива соответствующих размеров.
При повторном проходе положительные числа записываются
в первый массив, отрицательные — во второй.

Обход слева направо сохраняет порядок элементов внутри групп.
Нули пропускаются.

Положительные значения выводятся на первой строке,
отрицательные — на второй. Для формирования строк
используется StringBuilder.

### Асимптотика

**Время — O(n).**

Выполняется постоянное число линейных проходов:
чтение, распределение по группам и формирование вывода.

**Память — O(n).**

Хранятся исходный массив, массивы двух групп и строки результата.
Общее количество элементов в двух группах не превышает n.

### Примеры ручной проверки

**1. Разные знаки и нули**

Ввод:

```text
7
3 -2 0 5 -7 0 1
```

Ожидаемый вывод:

```text
3 5 1
-2 -7
```

Проверяются пропуск нулей и сохранение порядка.

**2. Только положительные числа**

Ввод:

```text
3
1 2 3
```

Ожидаемый вывод: первая строка содержит `1 2 3`,
вторая строка пустая.

Проверяется отсутствие отрицательной группы.

**3. Только нули**

Ввод:

```text
3
0 0 0
```

Ожидаемый вывод — две пустые строки.
Обе группы должны остаться пустыми.

## Задача 9. Проверка отсортированности

### Условие

Дан массив целых чисел. Требуется вывести YES, если массив
отсортирован по неубыванию, и NO в противном случае.

Равные соседние элементы допускаются.

### Идея решения

Флаг, указывающий на отсортированность, назван sorted. Проверяются два соседних элемента массива:
если i-ое число меньше (i-1)-го числа, то sorted = false, цикл сбрасывается. Иначе флаг не меняется и это говорит о том,
что массив отсортирован

### Асимптотика

**Время — O(n).**

Для чтения требуется O(n). Проверка выполняет не более n−1 сравнений.
Даже при досрочном завершении проверки чтение всего массива
уже потребовало O(n).

**Память — O(n).**

В данной реализации массив сохраняется в памяти.
Для проверки используется O(1) дополнительных переменных.

### Примеры ручной проверки

**1. Равные соседние элементы**

Ввод:

```text
5
1 2 2 3 3
```

Ожидаемый вывод:

```text
YES
```

Равенство не нарушает неубывание.

**2. Нарушение в середине**

Ввод:

```text
5
1 2 5 3 6
```

Ожидаемый вывод:

```text
NO
```

Пара 5 и 3 нарушает порядок.

**3. Нарушение в конце**

Ввод:

```text
4
1 2 4 3
```

Ожидаемый вывод:

```text
NO
```

Проверяется обработка последней пары.

## Задача 10. Поиск элемента с условием

### Условие

Дан массив целых чисел и ненулевое число k.
Требуется найти индекс последнего элемента, кратного k.

Если подходящих элементов нет, необходимо вывести −1.
Индексация начинается с нуля.

### Идея решения

Считываются массив и число k. Начальный ответ равен −1.

Массив просматривается справа налево.
Кратность проверяется условием numbers[i] % k == 0.

Первое найденное при таком обходе совпадение имеет
наибольший индекс. Этот индекс сохраняется, поиск завершается.

Ноль кратен любому ненулевому k. Отрицательные значения
элементов и k также корректно обрабатываются.

### Асимптотика

**Время — O(n).**

Чтение требует O(n). Поиск в худшем случае проверяет весь массив.

**Память — O(n).**

Хранится массив из n элементов.
Дополнительные переменные занимают O(1).

Ввод:


Ожидаемый вывод:


Последний элемент, кратный 3, — число 9 с индексом 4.

Проверяется отсутствие подходящих элементов.

## Задача 11. Ближайший к среднему

### Условие

Дан массив целых чисел. Требуется вывести элемент,
ближайший к среднему арифметическому массива.

Если несколько элементов имеют одинаковое расстояние
до среднего, выбирается первый по индексу.
Среднее может быть дробным.

### Идея решения

При чтении массив сохраняется и вычисляется сумма S типа long.

Вместо расстояния |a[i] − S/n| сравнивается величина:

```text
|a[i] * n − S|
```

Это исходное расстояние, умноженное на положительное n.
Такое преобразование сохраняет порядок расстояний
и позволяет избежать деления и ошибок округления.

Первым кандидатом становится элемент с индексом 0.
При дальнейшем проходе ответ обновляется только тогда,
когда найдено строго меньшее расстояние.

При равенстве расстояний прежний ответ сохраняется,
поэтому выбирается первый подходящий элемент.

Вычисления выполняются в long. При ограничениях задачи
сумма и масштабированные расстояния помещаются в этот тип.

### Асимптотика

**Время — O(n).**

Один проход нужен для чтения и суммы,
ещё один — для поиска ближайшего элемента.

**Память — O(n).**

Хранится исходный массив.
Остальные переменные занимают O(1).

### Примеры ручной проверки

**1. Элемент равен среднему**

Ввод:

```text
3
1 4 7
```

Ожидаемый вывод:

```text
4
```

Среднее равно 4, расстояние до выбранного элемента равно нулю.

**2. Дробное среднее**

Ввод:

```text
3
1 2 4
```

Ожидаемый вывод:

```text
2
```

Среднее равно 7/3. Ближайший элемент — 2.

**3. Равные расстояния**

Ввод:

```text
2
8 2
```

Ожидаемый вывод:

```text
8
```

Среднее равно 5. Оба числа находятся на расстоянии 3,
поэтому выбирается первое.

## Задача 12. Пара с заданной суммой

### Условие

Дан массив целых чисел и число s.
Требуется найти индексы i < j, для которых a[i] + a[j] = s.

При нескольких подходящих парах выбирается минимальный i,
а при одинаковом i — минимальный j.

Если пары нет, выводится −1 −1.

### Идея решения

Используется HashMap, в которой значению элемента соответствует
наименьший известный индекс этого значения справа от текущей позиции.

Массив просматривается справа налево.
Для очередного элемента вычисляется дополнение s − a[i].
Если оно есть в таблице, найдена подходящая пара.

Проверка выполняется до добавления текущего элемента,
поэтому элемент не может составить пару с самим собой.

После проверки текущее значение записывается в таблицу
с индексом i. При повторении значения прежний индекс заменяется
на меньший. Это обеспечивает минимальный j для следующего поиска.

Каждая новая найденная пара имеет меньший i, чем предыдущая,
поэтому ответ перезаписывается. После завершения обхода
сохраняется пара с минимальным i, затем с минимальным j.

Число s и дополнение хранятся в long, поскольку сумма двух int
может не поместиться в int.

### Асимптотика

**Время — O(n) в среднем.**

Каждый элемент обрабатывается один раз. На шаге выполняется
постоянное число операций с HashMap, имеющих среднюю стоимость O(1).
Оценка времени зависит от поведения хеш-таблицы.

**Память — O(n).**

Хранятся исходный массив и таблица, содержащая не более n значений.

### Примеры ручной проверки

**1. Одна подходящая пара**

Ввод:

```text
4
2 7 11 15
9
```

Ожидаемый вывод:

```text
0 1
```

Сумма элементов с индексами 0 и 1 равна 9.

**2. Выбор минимального первого индекса**

Ввод:

```text
4
5 2 3 0
5
```

Ожидаемый вывод:

```text
0 3
```

Есть пары (0,3) и (1,2). Выбирается (0,3).

**3. Выбор минимального второго индекса**

Ввод:

```text
5
2 1 3 3 3
5
```

Ожидаемый вывод:

```text
0 2
```

Для i = 0 подходят несколько индексов.
Нужен наименьший из них.

**4. Пары нет**

Ввод:

```text
3
1 2 3
20
```

Ожидаемый вывод:

```text
-1 -1
```

## Задача 13. Сортировка выбором

### Условие

Дан массив целых чисел. Требуется отсортировать его
по неубыванию методом выбора.

### Идея решения

Массив условно делится на отсортированную и неотсортированную части.

На каждом шаге находится индекс минимального элемента
неотсортированной части. Этот элемент меняется местами
с первым элементом рассматриваемой части.

После обмена отсортированная часть увеличивается на один элемент.
В ней находятся наименьшие элементы массива в правильном порядке.

Последний элемент отдельно обрабатывать не требуется:
после размещения остальных он уже находится на своём месте.

### Асимптотика

**Время — O(n²).**

Количество сравнений равно:

```text
(n − 1) + (n − 2) + … + 1 = n(n − 1) / 2
```

Даже для уже отсортированного массива поиск минимума
в каждой оставшейся части выполняется полностью.

**Общая память — O(n).**

Массив содержит n элементов.
Сортировка выполняется на месте и использует O(1)
дополнительной памяти.

### Примеры ручной проверки

**1. Неупорядоченные элементы**

Ввод:

```text
5
4 1 5 2 3
```

Ожидаемый вывод:

```text
1 2 3 4 5
```

Проверяется обычная сортировка.

**2. Повторения и отрицательные числа**

Ввод:

```text
5
3 -1 3 0 -1
```

Ожидаемый вывод:

```text
-1 -1 0 3 3
```

Повторяющиеся элементы должны сохраниться.

**3. Уже отсортированный массив**

Ввод:

```text
3
1 2 3
```

Ожидаемый вывод:

```text
1 2 3
```

Правильный порядок не должен нарушаться.

## Задача 14. Сортировка вставками

### Условие

Дан массив целых чисел. Требуется отсортировать его
по невозрастанию методом вставок.

### Идея решения

Первый элемент считается отсортированной частью массива.

Начиная со второго элемента, очередное значение сохраняется
во временную переменную. В отсортированной части все элементы,
меньшие сохранённого значения, сдвигаются на одну позицию вправо.

На освободившееся место записывается сохранённое значение.
После каждого шага обработанная часть массива упорядочена
по невозрастанию.

Сохранение очередного значения во временной переменной
не позволяет потерять его при сдвиге элементов.

### Асимптотика

**Время — O(n²) в худшем случае, O(n) в лучшем.**

В худшем случае очередной элемент перемещается через всю
обработанную часть. Общее число сдвигов может достигать n(n−1)/2.

Если массив уже отсортирован по невозрастанию,
внутренний цикл не выполняет сдвигов.

**Общая память — O(n).**

Массив хранится в памяти. Дополнительная память сортировки — O(1).

### Примеры ручной проверки

**1. Обычная сортировка**

Ввод:

```text
5
3 1 5 2 4
```

Ожидаемый вывод:

```text
5 4 3 2 1
```

Проверяется требуемое направление сортировки.

**2. Отрицательные числа и повторы**

Ввод:

```text
5
-2 3 -2 0 3
```

Ожидаемый вывод:

```text
3 3 0 -2 -2
```

**3. Уже правильный порядок**

Ввод:

```text
4
9 7 4 1
```

Ожидаемый вывод:

```text
9 7 4 1
```

Проверяется лучший случай без сдвигов.

## Задача 15. Пузырьковая сортировка с подсчётом обменов

### Условие

Дан массив целых чисел. Требуется отсортировать его
по неубыванию пузырьковым методом и подсчитать количество обменов.

Если очередной проход не выполнил ни одного обмена,
сортировка должна завершиться досрочно.

### Идея решения

Во время прохода сравниваются соседние элементы.
Если левый больше правого, они меняются местами,
а счётчик exchanges увеличивается.

После прохода наибольший элемент рассматриваемой части
оказывается справа. Поэтому правая граница следующего прохода
уменьшается на один.

Переменная changed показывает, были ли обмены.
Если обменов не было, все соседние пары упорядочены
и сортировка завершается.

Счётчик имеет тип long: максимальное количество обменов
может превышать диапазон int.

Массив выводится на первой строке, число обменов — на второй.

### Асимптотика

**Время — O(n²) в худшем случае, O(n) в лучшем.**

Для массива в обратном порядке выполняется квадратичное
число сравнений и обменов.

Для уже отсортированного массива достаточно одного прохода.

**Общая память — O(n).**

Дополнительная память сортировки — O(1).

### Примеры ручной проверки

**1. Несколько обменов**

Ввод:

```text
3
3 1 2
```

Ожидаемый вывод:

```text
1 2 3
2
```

Сначала меняются 3 и 1, затем 3 и 2.

**2. Уже отсортированный массив**

Ввод:

```text
4
1 2 3 4
```

Ожидаемый вывод:

```text
1 2 3 4
0
```

Проверяются нулевой счётчик и досрочное завершение.

**3. Обратный порядок**

Ввод:

```text
3
3 2 1
```

Ожидаемый вывод:

```text
1 2 3
3
```

Для трёх различных элементов это максимальное число обменов.

## Задача 16. Сортировка по модулю

### Условие

Дан массив целых чисел. Требуется отсортировать его
по неубыванию модуля элементов.

При равных модулях отрицательное значение должно идти
раньше положительного.

### Идея решения

Используется сортировка слиянием.

Массив рекурсивно делится на две половины.
После сортировки половин они объединяются во временном массиве,
затем результат копируется обратно.

При сравнении сначала рассматриваются модули чисел.
Если модули равны, сравниваются сами значения:
меньшее, то есть отрицательное, располагается раньше.

Перед вычислением модуля число преобразуется к long.
Это необходимо для Integer.MIN_VALUE, положительный модуль
которого не помещается в int.

### Асимптотика

**Время — O(n log n).**

На каждом уровне рекурсии суммарно обрабатывается O(n) элементов.
Количество уровней — O(log n).

**Общая и дополнительная память — O(n).**

Используются исходный массив и буфер длины n.
Стек рекурсии занимает O(log n), что не меняет общую оценку.

### Примеры ручной проверки

**1. Разные модули и знаки**

Ввод:

```text
6
-3 1 0 2 -1 3
```

Ожидаемый вывод:

```text
0 -1 1 2 -3 3
```

Проверяются порядок модулей и выбор отрицательного при равенстве.

**2. Одинаковые модули**

Ввод:

```text
4
2 -2 2 -2
```

Ожидаемый вывод:

```text
-2 -2 2 2
```

Все повторения должны сохраниться.

**3. Крайние значения int**

Ввод:

```text
3
-2147483648 2147483647 0
```

Ожидаемый вывод:

```text
0 2147483647 -2147483648
```

Модуль Integer.MIN_VALUE больше модуля Integer.MAX_VALUE.

поэтому вычисление суммы цифр имеет ограниченную стоимость.

**Общая и дополнительная память — O(n).**

Создаётся временный буфер длины n.
Стек рекурсии требует O(log n).

Суммы цифр равны соответственно 0, 3, 5 и 18.

**2. Сохранение исходного порядка**

Ввод:

```text
7

```

Ожидаемый вывод:

```text
0 21 12 3 30 4 40
```

Числа 21, 12, 3 и 30 имеют сумму цифр 3
и сохраняют взаимный порядок. Аналогично сохраняется порядок 4 и 40.

**3. Только нули**

Ввод:

```text
3
```

Ожидаемый вывод:

Проверяется обработка нуля и одинаковых ключей сортировки.

## Задача 18. Сортировка только чётных

### Условие

Дан массив целых чисел. Требуется отсортировать только
чётные значения по неубыванию.

Нечётные элементы должны остаться на исходных местах.
Чётность определяется значением элемента, а не его индексом.

### Идея решения

При чтении массива подсчитывается количество чётных элементов k.

Создаётся отдельный массив even длины k.
При проходе по исходному массиву в него копируются
все чётные значения.

Массив even сортируется слиянием.
Затем выполняется ещё один проход по исходному массиву:
на каждое место чётного элемента записывается очередное
значение из отсортированного even.

Нечётные элементы не изменяются. Ноль и отрицательные
чётные числа обрабатываются как обычные чётные значения.

### Асимптотика

**Время — O(n + k log k), где k — количество чётных элементов.**

Чтение, выделение чётных значений и их возвращение требуют O(n).
Сортировка k элементов требует O(k log k).

При k = 0 или k = 1 сортировать фактически нечего,
поэтому общее время составляет O(n).
В худшем случае k = n и время равно O(n log n).

**Общая память — O(n + k), то есть O(n).**

Исходный массив содержит n элементов.
Массив чётных значений и буфер содержат по k элементов.
Дополнительная память сверх исходного массива — O(k)
для k ≥ 1; при k = 0 она постоянная.

### Примеры ручной проверки

**1. Чётные и нечётные значения**

Ввод:

```text
6
8 3 2 5 6 1
```

Ожидаемый вывод:

```text
2 3 6 5 8 1
```

Чётные значения 8, 2 и 6 сортируются.
Нечётные 3, 5 и 1 остаются на прежних индексах.

**2. Чётных элементов нет**

Ввод:

```text
4
7 -3 5 1
```

Ожидаемый вывод:

```text
7 -3 5 1
```

Массив не изменяется.

**3. Ноль и отрицательные чётные числа**

Ввод:

```text
5
0 7 -4 3 -2
```

Ожидаемый вывод:

```text
-4 7 -2 3 0
```

Проверяется правильный порядок всех чётных значений.

## Задача 19. Объединение двух отсортированных массивов

### Условие

Даны два массива, отсортированных по неубыванию.
Требуется объединить их в один отсортированный массив.

Ввод: размер n и первый массив, затем размер m и второй массив.

### Идея решения

Создаётся массив результата длины n+m.

Для каждого исходного массива используется свой указатель,
показывающий на следующий ещё не перенесённый элемент.

Пока в обоих массивах остаются элементы, сравниваются
текущие значения. Меньшее переносится в результат,
а соответствующий указатель увеличивается.

Когда один массив заканчивается, оставшиеся элементы
другого копируются в результат без дополнительных сравнений:
они уже отсортированы.

Каждый элемент переносится ровно один раз.
Исходные массивы не изменяются.

### Асимптотика

**Время — O(n + m).**

Чтение, слияние и формирование вывода обрабатывают
линейное количество элементов.

**Общая память — O(n + m).**

Хранятся два исходных массива, массив результата
и StringBuilder для вывода.
Их суммарный размер линейно зависит от n+m.

### Примеры ручной проверки

**1. Чередующиеся значения**

Ввод:

```text
3
1 3 5
3
2 4 6
```

Ожидаемый вывод:

```text
1 2 3 4 5 6
```

Элементы последовательно выбираются из обоих массивов.

**2. Повторяющиеся значения**

Ввод:

```text
2
1 3
3
1 2 3
```

Ожидаемый вывод:

```text
1 1 2 3 3
```

Совпадающие значения не удаляются.

**3. Первый массив заканчивается раньше**

Ввод:

```text

-5 -1
3
0 2 4
```

Ожидаемый вывод:

```text

```

Проверяется копирование оставшейся части второго массива.

## Задача 20. Сортировка подсчётом

### Условие

Дан массив из n целых чисел, 1 < n < 100000. Необходимо отсортировать его по неубыванию методом подсчёта.

Ввод: сначала n, затем n элементов типа int. Вывод: отсортированные числа через пробел, затем перевод строки.

### Идея решения

Сначала находятся минимум min и максимум max. Размер диапазона R = max − min + 1 вычисляется в long: разность крайних int не помещается в int.

Если R не больше 1 000 000, используется обычная сортировка подсчётом. Массив counts хранит частоты: counts[value − min] соответствует значению value. Смещение позволяет работать с отрицательными числами. При проходе по счётчикам каждое значение записывается в новый массив нужное количество раз. Поскольку счётчики просматриваются по возрастанию, результат отсортирован и содержит все исходные значения с сохранением количества повторений.

Если диапазон шире, используется поразрядная сортировка с четырьмя стабильными проходами подсчёта по байтам. Это расширение обычного подсчёта для полного диапазона int: каждый проход использует всего 256 счётчиков. Готовые функции сортировки в решении не используются.

Для правильного порядка отрицательных и положительных чисел у ключа инвертируется знаковый бит. При беззнаковом рассмотрении ключ Integer.MIN_VALUE становится равным 0, а ключ Integer.MAX_VALUE — 2^32−1. Таким образом, порядок ключей совпадает с обычным порядком исходных целых чисел. В массиве при этом остаются исходные значения.

Обработка начинается с младшего байта и заканчивается старшим. Накопленные частоты задают границы групп. Запись элементов обратным обходом сохраняет относительный порядок элементов с одинаковым текущим байтом. Поэтому после каждого прохода числа упорядочены по уже обработанным байтам, а после четвёртого — полностью.

Порог 1 000 000 ограничивает только размер массива прямых счётчиков, примерно 4 МБ. Он не ограничивает допустимый ввод: широкий диапазон обрабатывается другим вариантом. Исключение из-за большого разброса значений не выбрасывается. Оба варианта возвращают новый массив, исходный не изменяется.

### Соответствие формулировке

Для компактного диапазона реализована классическая сортировка подсчётом. Для широкого — поразрядный алгоритм, каждый проход которого является стабильной сортировкой подсчётом. Различие указано явно: это не один прямой массив частот для всего диапазона int.

Исходное условие не ограничивает разброс значений. Прямой массив частот для пары Integer.MIN_VALUE и Integer.MAX_VALUE потребовал бы 2^32 счётчиков, что практически неприменимо. Выбранный вариант обрабатывает и такие данные. Если преподаватель подразумевает исключительно классический одношаговый подсчёт, нужно согласовать диапазон значений или разрешение поразрядного варианта; автоматически гарантировать принятие этой трактовки нельзя.

### Асимптотика

Обозначим через R величину max−min+1.

**Обычный подсчёт:**

- Время — O(n + R): поиск границ, подсчёт частот и запись n элементов линейны; дополнительно просматриваются R счётчиков.
- Общая память — O(n + R): исходный массив, массив результата и счётчики.

**Поразрядный вариант:**

- Время — O(4 × (n + 256)): выполняются четыре прохода по байтам 32-битного числа. Для фиксированного int это O(n).
- Общая память — O(n + 256): исходный массив, два рабочих массива длины n и 256 счётчиков. Рабочие массивы повторно используются между проходами.

Для обоих вариантов память сверх исходного массива имеет тот же порядок, что и общая оценка.

### Примеры ручной проверки

**1. Повторяющиеся значения**

Ввод:

```text
6
4 2 4 1 2 3
```

Ожидаемый вывод:

```text
1 2 2 3 4 4
```

Проверяется восстановление всех повторений.

**2. Отрицательные числа и ноль**

Ввод:

```text
5
-2 0 3 -1 0
```

Ожидаемый вывод:

```text
-2 -1 0 0 3
```

Проверяется смещение индексов в обычном подсчёте.

**3. Полный диапазон int**

Ввод:

```text
5
2147483647 -1 0 -2147483648 1
```

Ожидаемый вывод:

```text
-2147483648 -1 0 1 2147483647
```

Проверяются отсутствие переполнения диапазона и порядок знаков в поразрядном варианте.

**4. Граница выбора варианта**

Ввод:

```text
4
-500000 499999 0 -500000
```

Ожидаемый вывод:

```text
-500000 -500000 0 499999
```

Здесь R = 1 000 000 и применяется прямой подсчёт. Замена 499999 на 500000 увеличивает R до 1 000 001: применяется подсчёт по байтам, результат остаётся корректно отсортированным.

**5. Все элементы равны**

Ввод:

```text
4

```

Ожидаемый вывод:

```text

```

Диапазон R равен 1. Все элементы должны сохраниться.

## Задача 24. Чётно-нечётная сортировка

### Условие

Дан массив из n целых чисел.

Требуется вывести сначала все чётные элементы
по неубыванию, затем все нечётные по невозрастанию.
Повторяющиеся значения должны сохраниться.

Ввод: размер n, затем n элементов массива.
Вывод: элементы в требуемом порядке через пробел.

### Идея решения

Сначала весь массив сортируется по возрастанию
методом слияния.

Массив делится на две половины. Каждая половина
сортируется отдельно, после чего они объединяются.
При объединении выбирается меньший из доступных элементов.
Для промежуточного результата используется общий
вспомогательный массив.

После сортировки выполняются два прохода.

Первый проход идёт слева направо и выводит только
чётные числа. Поскольку массив отсортирован,
они выводятся по неубыванию.

Второй проход идёт справа налево и выводит только
нечётные числа. Обратный порядок обхода обеспечивает
их вывод по невозрастанию.

Ноль считается чётным. Для нечётных чисел используется
проверка остатка != 0, поскольку у отрицательного
нечётного числа остаток от деления на 2 равен −1.

Каждый элемент выводится ровно один раз:
либо при первом, либо при втором проходе.
Поэтому значения и количество повторений сохраняются.

### Асимптотика

**Время — O(n log n).**

На каждом уровне сортировки слиянием суммарно
обрабатывается O(n) элементов.
Число уровней равно O(log n).

Два прохода для вывода требуют O(n),
поэтому итоговая сложность остаётся O(n log n).

**Общая память — O(n).**

Хранятся исходный массив и вспомогательный массив
для слияния, каждый длины n.

**Дополнительная память — O(n).**

Буфер слияния занимает O(n), стек рекурсии — O(log n).
Итоговая дополнительная память составляет O(n).

### Примеры ручной проверки

#### 1. Чётные и нечётные числа

Ввод:

```text
6
5 2 3 4 1 6
```

Ожидаемый вывод:

```text
2 4 6 5 3 1
```

Проверяются порядок групп и направление сортировки
внутри каждой группы.

#### 2. Отрицательные числа и ноль

Ввод:

```text
6
-5 -2 3 0 -4 -1
```

Ожидаемый вывод:

```text
-4 -2 0 3 -1 -5
```

Проверяется обработка отрицательных нечётных чисел
и включение нуля в группу чётных.

#### 3. Только чётные числа

Ввод:

```text
4
8 0 -2 4
```

Ожидаемый вывод:

```text
-2 0 4 8
```

Отсутствие нечётных элементов не должно приводить
к появлению лишних значений или пробелов.

#### 4. Только нечётные числа

Ввод:

```text
4
1 -3 9 5
```

Ожидаемый вывод:

```text
9 5 1 -3
```

Проверяется вывод по невозрастанию,
когда первая группа пуста.

#### 5. Повторяющиеся значения

Ввод:

```text
6
3 2 1 3 4 2
```

Ожидаемый вывод:

```text
2 2 4 3 3 1
```

Проверяется сохранение всех повторений.

## Задача 56. Умножение матриц

### Условие и формат

Требуется получить: матрица C = A x B размера n x k.

**Ввод:** Три размера n m k, затем матрица A размера n×m и матрица B размера m×k.

### Идея решения

Для каждого результата вычислить скалярное произведение строки A и столбца B. Сумму хранить в BigInteger; готовую ячейку сразу печатать.

### Асимптотика

- Время: O(nmk) арифметических операций.
- Память: O(nm+mk); сверх входных матриц O(1) чисел.

Вычисляются n*k ячеек, каждая — сумма m произведений. Хранятся обе входные матрицы; ячейки результата печатаются сразу, отдельная матрица C не создаётся. В условии указана память O(nk). Здесь она трактуется как дополнительная память сверх входных матриц: результат выводится сразу. Полная память программы O(nm + mk), поэтому при требовании учитывать входные матрицы трактовку следует уточнить. Оценки операций с BigInteger приведены по числу арифметических действий; их битовая стоимость зависит от длины чисел.

### Примеры ручной проверки

## Задача 60. Острова из единиц

Требуется получить: количество «островов» — групп связанных единиц (связь по горизонтали и вертикали, не по диагонали).
